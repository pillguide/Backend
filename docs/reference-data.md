# 약 참조자료·병용금기 계약 (구현 목표)

> 2026-11-11 승인된 수집·표시 목표다. 이 문서의 신규 필드, 갱신 작업, 4쌍 적재, 이미지 준비는 구현 및 실제 자료 검증 전까지 완료 상태가 아니다. 기준: 2026-11-11 구현 계획과 2026-10-19 식약처 선별 필드 검토.

## 식별자와 저장 경계

- AI 모델의 150개 `item_seq`를 **문자열 identity**로 유지한다. `Drug.code`의 기존 고유성과 ID·참조 관계를 보존한다. 공식 자료가 없거나 허가 상태가 달라져도 품목을 삭제하거나 이름 유사도로 다른 품목에 연결하지 않는다.
- 기존 `Drug.name`, `imageUrl`, `DrugInfo`의 `effect`, `dosageMethod`, `storageMethod`, `sideEffects`와 검색·상세 응답을 유지한다. 공식명/모델명, 성분·분류, 허가·자료 상태, 출처·수집 시점, 대표 이미지 object key·hash/버전은 필요한 필드로 확장한다. 만료 URL을 영구 저장하지 않는다.
- 요청 중 식약처 API를 호출하지 않는다. 수집기는 허용한 필드만 선별하고 원문 숫자·조건·표·주석을 보존한다. API 전체 payload, 인증 정보, 오류 원문을 DB에 복사하지 않는다. 출처별 정상 빈 응답과 실패를 별도 상태로 구분한다. 이전 조사 수치(예: 42/150, 33/30)는 현재 DB 행 수가 아니다.
- 주성분 행은 코드가 같아도 원천 행 단위로 보존한다. 함량·단위를 임의 환산하지 않는다. 문자열 성분 코드의 선행 0을 보존한다. 자료 누락은 안전·무효·해당 없음으로 번역하지 않는다. 허가 상태는 사용자가 보유한 알약의 유효기간이나 복용 가능 여부가 아니다.

## 승인된 비교 범위

현재 사진에 검출된 **고유 품목**의 모든 쌍을 만들어 아래 네 쌍과 일치하는지 확인한다. 방향을 바꿔도 같은 쌍이다. 직접 품목 근거 3쌍과 공식 성분코드 연결 1쌍을 구분한다. 동일 성분·유사명이라는 이유로 새 금기를 추론하지 않는다.

| 품목번호 A | 품목번호 B | 표시명 | 근거 |
|---|---|---|---|
| `197500541` | `200001783` | 구주스피로닥톤정 / 케이콘틴서방정 | 직접 품목 |
| `199906953` | `201401986` | 클래리시드엑스엘서방정500mg / 트루패스정4mg | 직접 품목 |
| `199906953` | `201606824` | 클래리시드엑스엘서방정500mg / 콜키닌정 | 직접 품목 |
| `200811061` | `201309347` | 액티프롤정 / 아질렉트정 | 공식 성분코드 연결 |

한 쌍의 공식 근거가 여러 건이면 배열로 모두 보존한다. 각 근거의 직접/성분 유형, 원천 식별자, 공식 사유·조건, 날짜와 연결 증거를 분리한다. 사유가 빈 근거도 삭제하지 않는다. 검수한 짧은 설명은 공식 원문과 별도로 저장하고 원천 hash에 묶는다. 원문 변경 때 옛 설명을 새 자료에 붙이지 않는다. 사용자 스캔 요청에서는 설명 생성 모델을 호출하지 않는다. 네 쌍의 변경·삭제·새 공식 금기 등 승인 범위를 바꾸는 발견은 보고 후 결정한다.

## 수집·갱신·제공 상태

- 최초 적재 전에 공식 API 현재 응답, 150개 identity 매핑, 네 쌍의 원문·조건을 다시 검증한다. 일 10,000건은 사용자 제시 상한이며 실제 API/계정별 한도를 확인한다. dev의 초기 자동 수집 예산 제안은 재시도 포함 최대 2,000건/일이다. 일 1회가 기본이며 완전 수집·실제 한도에 맞춰 주 단위도 설정할 수 있다.
- 실행기 겹침을 막고 일일 호출 사용량과 성공·실패를 재시작 후에도 보존한다. 429/일시 장애만 제한적으로 재시도한다. 페이지 누락·반복, 품목 코드 불일치, 본문 오류, 불완전 자료는 성공으로 게시하지 않는다. 기존 복약·FCM 실행기를 막지 않는다.
- 수집·정제·검증은 DB 쓰기 트랜잭션 밖에서 완료한다. 검증한 150품목, 승인된 네 쌍, 현재 버전을 짧은 일괄 트랜잭션으로 교체한다. 실패하면 마지막 정상 자료를 유지한다. 분석 요청은 한 버전의 일관된 snapshot을 읽고 당시 결과·버전을 이력에 복사한다.
- 마지막 정상 자료에는 기준일과 갱신 지연 상태를 붙여 계속 제공한다. 날짜 경과만으로 전시 기간에 자동 중단하지 않는다. 최초 정상 자료가 없거나 무결성이 깨지면 성공 비교로 표시하지 않고 503 또는 내부 오류로 구분한다. 네 쌍에 미일치하면 **검수된 참조 목록에서 금기를 확인하지 못함**으로 표시한다.

## 대표 이미지

사용자가 2026-11-12부터 GPU 서버에 접근할 수 있다고 확인했다. 그때 데이터셋의 각 `item_seq`/`product_code`와 원본을 대조해 **품목당 앞면 원본 한 장**을 선별한다. 파일 존재만으로 매핑을 인정하지 않고 원본·선택 파일·hash·버전 및 렌더링을 확인한다. 추후 S3에는 대표 이미지만 저장하고 DB에는 object key를 둔다. 사용자 사진·crop은 S3와 DB에 영구 저장하지 않는다. 공개 버킷 전환 없이 필요한 조회에서 접근 URL을 발급한다. 150장 매핑·실제 비교 렌더링 검증 전에는 이미지 준비 완료로 보고하지 않는다.

## 전환·검증 관문

기존 `Drug`, `DrugInfo`, `ScanSession`, `ScanDrug` 행과 외래키를 보존한다. 새 컬럼은 과거 행에 적용 가능한 nullable/default 설계로 추가하고, 고유 제약 전 중복을 검사한다. 중복 데이터를 임의 삭제하지 않는다. `MemberDrug`는 회원·품목 관계만 보유하며 기존 약·스캔·복약을 연쇄 삭제하지 않는다. `DrugInteraction`은 정렬된 두 품목 ID에 고유 제약과 `low_id < high_id` 검사를 둔다.

실제 dev DB의 테이블·행 수·중복·null·참조 무결성과 150개 매핑은 **아직 이 문서에서 조회하지 않았다**. 반복 적용 가능한 전환 SQL 및 현재 스키마 대조 결과가 확인된 뒤에만 `ddl-auto=validate` 전환을 준비한다. 과거 스캔에 존재하지 않았던 confidence, bbox, 병용 snapshot을 추정해 채우지 않는다.
