# 식약처 참조자료 수집·갱신

`ReferenceSyncCoordinator`가 수집 → 검증 → 게시를 수행한다. 스캔 요청에서는 식약처를 호출하지 않는다. 모델의 150개 품목번호와 승인된 병용금기 4쌍이 모두 검증되어야 현재 자료를 갱신한다. 정상 빈 조회는 `NO_DATA`, 통신·본문·페이지 오류는 실행 실패다.

## 실행 설정

| 설정 | 기본값 | 의미 |
|---|---|---|
| `reference.sync.enabled` | `false` | 전용 작업자 활성화. 필요한 키·전환 SQL 준비 후 dev에서 켠다. |
| `reference.sync.refresh-days` | `7` | 마지막 성공 후 갱신 주기. 1로 설정하면 일 단위 갱신. |
| `reference.sync.daily-request-limit` | `2000` | KST 당일 실제 HTTP 시도 예산. 재시도와 모든 출처를 합산한다. 설정 상한 10,000. |
| `reference.sync.lease-seconds` | `1800` | 작업 소유권 만료. 각 요청 예약 시 연장. |
| `reference.mfds.easy-key` | 기존 `drug.easy.service-key` | e약은요 키 |
| `reference.mfds.permit-key` | 기존 `drug.prmsn.service-key` | 허가 목록·상세·주성분 키 |
| `reference.mfds.dur-product-key` | 없음 | DUR 품목 키 |
| `reference.mfds.dur-ingredient-key` | 없음 | DUR 성분 키 |

키는 **일반 인증키(Decoding)** 값을 비밀 설정으로 주입한다. URL이나 프런트에 노출하지 않는다. 인코딩은 HTTP 클라이언트가 수행한다. 이 작업 외의 계정 소비량은 추적할 수 없으므로 2,000건은 프로젝트 내부 예산이며 공공데이터 계정 전체 잔여량을 보장하지 않는다.

활성화한 작업자는 시작 60초 뒤, 이후 하루 간격으로 갱신 필요 여부를 확인한다. 마지막 성공 후 7일이 지나야 새 수집을 시작하고 실패한 실행은 최소 24시간 뒤 재시도한다. 별도 단일 작업자를 사용하여 기존 복약 알림 작업자를 점유하지 않는다. 재시작·여러 서버의 동시 실행은 DB의 한 상태 행으로 조정한다. 외부 공개 수집 API는 없다.

HTTP 연결 제한 10초, 응답 전체 제한 45초, 요청 간 최소 간격 400ms, 일시 통신 오류/429/5xx에 한해 최대 2회 재시도한다. 응답 최대 8MiB, 출처별 최대 200페이지이며 품목번호·총 건수·반복/누락 페이지를 검사한다. 비밀키와 오류 원문은 응답·로그·실행 상태에 저장하지 않는다.

## 저장과 실패 처리

수집은 DB 트랜잭션 밖에서 진행한다. `reference_sync_state` 한 행의 잠금은 실행 시작·각 호출 예약·최종 게시 때만 사용한다. 호출 예약은 독립적으로 커밋되어 수집 실패나 서버 재시작으로 당일 사용량이 사라지지 않는다. 중단한 작업의 소유권은 만료 후 다른 실행이 인계하며, 이전 실행은 새 실행의 상태를 변경하거나 자료를 게시할 수 없다.

검증된 후보는 짧은 트랜잭션에서 기존 `Drug`·`DrugInfo` 식별자를 보존하며 갱신한다. 승인된 4쌍과 현재 자료 버전도 같은 트랜잭션으로 갱신한다. 실패 시 전체가 롤백되고 마지막 정상 버전·성공 시각을 보존한다. 모델 지원 범위 밖의 기존 약 마스터는 삭제하지 않는다.

선택 필드는 `DrugInfo.selectedSourcesJson`에 보존한다. 허가 문서 XML/HTML, 숫자·단위·조건·표는 원문을 유지한다. DUR 품목 조회의 상태·전체 건수는 남기되, DB의 근거 행은 승인된 지원 품목쌍으로 제한한다. `recordCount`와 저장한 `records`의 길이는 이 필터 때문에 다를 수 있다. 일반 약 전체의 금기를 수집·추론하는 서비스가 아니다.

허가 상태 `NORMAL`은 공식 `CANCEL_NAME=정상`, `ABNORMAL`은 그 밖의 명시된 상태, `UNKNOWN`은 상태 누락, `NO_OFFICIAL_RECORD`는 허가 자료 부재다. `ABNORMAL`을 모두 취하로 바꾸지 않으며 원문 상태를 함께 보존한다. 정보 상태 `COMPLETE/PARTIAL/NO_OFFICIAL_RECORD`는 출처 확보 정도이고 복용 안전 판정이 아니다.

네 쌍의 품목·성분 연결·금기 사유·조건이 달라지거나 새로운 지원 품목쌍이 발견되면 게시를 중단한다. 원문을 검토하고 사용자 결정을 받은 후 승인 목록/설명을 변경한다. 검수 설명은 검증한 근거 해시에 연결한다. 최초 정상 버전이 없으면 이후 스캔 처리는 참조자료 미준비로 응답하고, 갱신 실패만으로 기존 정상 자료를 폐기하지 않는다.

## 전환과 검증

`docs/sql/reference-scan-state.sql` 다음에 `docs/sql/reference-sync-state.sql`을 적용한다. 실제 dev 적용은 해당 배포 단계에서 별도로 수행한다. 현재 SQL 작성 자체는 배포나 원격 DB 변경이 아니다.

- `test`: HTTP 모사 서버의 페이지·응답·재시도·키 비노출 및 수집기의 근거 변경 거절.
- `postgresTest`: 실제 격리 PostgreSQL의 실행권·예산·만료·동시성·전체 게시 롤백.
- `mfdsLiveTest`: 명시적 `MFDS_LIVE_TEST=true`, loopback 테스트 DB `jdbc:postgresql://127.0.0.1:55432/pillguide_test`, 4개 `MFDS_*_KEY` 환경변수로만 실행하는 실제 API 검증. 기본 검사에는 포함하지 않는다. DB를 생성·삭제하는 테스트이므로 dev/prod 연결은 허용하지 않는다.

대표 이미지 취득·S3 준비는 별도 단계다. 식약처 사진 URL을 데이터셋 대표 이미지로 임의 대체하지 않는다.
